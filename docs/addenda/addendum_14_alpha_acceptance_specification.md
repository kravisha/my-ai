## Canonical acceptance criteria for the agent ecosystem

### Purpose

Define exactly what must be demonstrably working before the system is considered to have reached Alpha. This specification focuses on agent existence, lifecycle, observability, human queryability, queue-based communication, simulated operation, and the minimum organizational behaviors required before historical-data Beta.

### 1. Alpha Objective

**The organization must be alive, observable, addressable, and ready to work.**

Alpha establishes that the agent organization exists as a functioning, inspectable system. Required agents can be instantiated, remain alive, identify themselves, expose status, communicate through the defined infrastructure, accept simulated work, and be inspected by the authorized superuser.

- Alpha is not merely a collection of processes that happen to be running.
- Business intelligence is driven by simulated data during Alpha.
- Historical market data is reserved for Beta.
- Banker may exist as a stub/alive agent during Alpha, but its full client-service behavior is deferred to Alpha Plus.

### 2. Phase D Relationship

Phases A through C are defined elsewhere. At the end of Phase C, the required agents are expected to exist and be running but may be idle because meaningful work has not yet been supplied.

- Phase D introduces the Simulation Experiment Framework.
- Phase D supplies controlled work to agents for training, testing, grading, and end-to-end synthetic operation.
- Simulation must use the same fundamental request/queue infrastructure intended for later operation.
- Changing from simulation to historical or live data should change the data source, not create a second organizational architecture.

### 3. Required Alpha Agent Population

- Controller Agent.
- COO Agent, temporarily performing bootstrap responsibilities that will later belong to Bob/CEO.
- HR Agent.
- Explorer Analyst.
- Speculator Analyst.
- Analysis Analyst.
- Explorer Trainer.
- Speculator Trainer.
- Analysis Trainer.
- Executive Trainer.
- Required independent evaluation capability.
- Portfolio Analysis Agent.
- Banker Agent stub/alive presence.

Bob/CEO is not required for the present Alpha. When Bob is implemented, the startup sequence will change so Controller creates Bob first and Bob assumes CEO authority.

### 4. Agent Instantiation Acceptance

- Every required Alpha agent type is instantiatable through the defined lifecycle mechanism.
- Controller is the exclusive runtime authority that physically creates agent processes.
- Each created agent receives an immutable internal ID and configured human-readable name.
- Each agent receives the correct role definition and lifecycle state.
- Each agent registers its health/status and request queue.
- Each agent becomes visible through system observability.
- Creation failures are reported explicitly and do not silently produce partially registered agents.

### 5. Alive and Idle-Ready State

**Idle is a valid operating state.**

- An idle agent remains healthy and alive.
- It emits or exposes required heartbeat/health information.
- It monitors its request queue.
- It remains queryable through the authorized human interface.
- It maintains its organizational identity and role.
- It does not invent work merely because it is idle.
- It remains ready to accept legitimate assigned work.

### 6. Minimum Agent Self-Awareness

Every Alpha agent must possess enough operational self-awareness to answer basic questions about its organizational identity and current state. This does not mean unrestricted introspection into hidden model internals.

- Who are you?
- What is your configured agent name?
- What is your immutable agent ID?
- What type of agent are you?
- What is your organizational role?
- What are your responsibilities?
- What are you allowed to do?
- What are you not allowed to do?
- What skills or competencies are assigned to you?
- What is your current lifecycle state?
- Are you healthy?
- Are you currently working or idle?
- What task are you performing, if any?
- What request queue or work mechanism do you monitor?
- What configuration/version are you operating under, where relevant?

Exact wording is not important. Correctness and consistency are.

### 7. Universal Human Query Interface (UQI)

**The UQI is for human-to-agent interaction only. It is not an inter-agent communication mechanism.**

- The server/controller interface exposes a control that can open a client-style query window.
- An authorized superuser can select an agent from a list/drop-down and open a direct human query session with that agent.
- The superuser may query COO, HR, trainers, analysts, evaluators, Portfolio Analysis, Banker, and future Bob when implemented.
- The UQI is intended for development, inspection, supervision, diagnosis, testing, and privileged administration.
- Direct UQI access must be privilege-controlled and auditable.
- Ordinary external clients do not receive unrestricted UQI access to internal agents.
- When the Banker client-service layer becomes active, ordinary clients communicate through Banker unless another client-facing role is explicitly introduced.

### 8. Inter-Agent Communication Boundary

**Agents do not use the UQI to communicate with one another.**

- Inter-agent work is communicated through structured requests/messages submitted through the defined queue/database infrastructure.
- Requests must be attributable and persistable.
- The queue/request mechanism is the organizational communication fabric.
- Explorer-Speculator corroboration, training assignments, Analysis handoffs, lifecycle requests, and other organizational work use formal contracts rather than hidden direct chat.
- Human inspection must not accidentally become a second production communication path.

### 9. Phase D Simulation Experiment Framework

- Each experiment identifies the target agent/role and target skill.
- Each experiment defines success criteria and hidden ground truth where applicable.
- The Simulation Engine generates the required synthetic data/environment.
- The Training Agent administers the exercise through normal organizational task mechanisms.
- The target agent performs the task as it would in normal operation.
- The Training Agent/evaluator captures the result, grades it, provides feedback, and persists the evidence.
- Experiments are reusable, versioned, reproducible, and become part of an expanding experiment library.
- Skills are first-class objects; experiments exist to train or validate defined skills.

### 10. Synthetic End-to-End Alpha Operation

- Explorer receives synthetic market/options data, constructs volatility surfaces, and searches for planted or emergent anomalies.
- Speculator receives synthetic chatter/context streams and searches for meaningful signals while rejecting noise.
- Explorer and Speculator cross-check meaningful findings using formal queue-based request contracts.
- Qualified evidence is handed to Analysis.
- Analysis performs deeper reasoning, produces an opportunity assessment, and grades upstream work.
- Training and evaluation results persist and feed organizational learning.
- The entire loop runs repeatedly and continuously for an extended Alpha period.
- Ordinary/no-signal periods are valid and should not force reports.

### 11. Portfolio Analysis During Alpha

- Portfolio Analysis Agent should be instantiatable, alive, queryable, and trainable during Alpha.
- Its analysis behavior may be exercised with simulated client portfolios and simulated organizational intelligence.
- It remains architecturally separate from continuous Explorer/Speculator discovery.
- Full Banker-mediated client experience is deferred to Alpha Plus, but Portfolio Analysis itself should be capable of synthetic testing in Alpha.

### 12. Banker Treatment in Alpha and Alpha Plus

- Banker exists in Alpha as an instantiatable/alive/stubbed role so lifecycle, identity, health, and UQI inspection can be proven.
- Banker does not need full client relationship functionality to pass Alpha.
- Alpha Plus activates the Banker role and tests it with simulated client conversations, preferences, objectives, relationship memory, clarification behavior, and Portfolio Analysis orchestration.
- After Alpha Plus succeeds, Beta moves the broader organization to historical market data.

### 13. Alpha Health and Observability

- Every agent exposes current lifecycle state and health.
- Agent creation, restart, suspension/retirement, and failures are logged.
- Queue state and task routing are observable.
- Training runs, grades, feedback, and agent performance records persist.
- Agent failures must be detectable and recoverable according to lifecycle policy.
- The organization must not depend on a human keeping an agent window open for the agent to remain alive.

### 14. Alpha Stability Requirement

**Alpha must run as one whole synthetic organization for an extended period, not merely pass isolated unit demonstrations.**

- All required agents remain operational or recover correctly from expected failures.
- No systemic deadlock or uncontrolled task accumulation.
- No silent loss of requests, grades, or required organizational records.
- No role repeatedly performs work outside its defined responsibility.
- Simulation continues to produce realistic workload patterns.
- Health, throughput, latency, quality, and recovery milestones remain within the Alpha thresholds defined by the implementation team.
- The exact required continuous-run duration and numeric performance thresholds must be explicitly configured before Alpha graduation.

### 15. Alpha Acceptance Checklist

- All required agent types can be instantiated.
- All required agents can remain alive while idle.
- All required agents are visible in system status/observability.
- Every agent can correctly answer basic questions about itself.
- Superuser can open the UQI and directly query any authorized internal agent.
- Ordinary clients cannot use the privileged UQI to bypass client-facing boundaries.
- Inter-agent communication occurs through formal queue/database requests, not UQI chat.
- Phase D Simulation Experiment Framework can create, administer, grade, and persist reproducible experiments.
- Explorer, Speculator, and Analysis can operate independently and as an end-to-end synthetic analysis team.
- Portfolio Analysis can be synthetically exercised.
- Banker stub can be instantiated and inspected.
- Grades, training history, knowledge, agent records, and relevant state survive process restart.
- The complete synthetic organization runs continuously for the required Alpha period and satisfies configured performance and recovery milestones.

### 16. Graduation Path

- **Pre-Alpha:** metadata, contracts, persistence abstraction, agent population, skill catalogs, and simulation foundations.
- **Alpha:** full organization continuously operational on simulated data, with UQI, training, evaluation, and end-to-end synthetic market workflow.
- **Alpha Plus:** activate and train the Banker/client relationship layer using simulated client data and interactions.
- **Beta:** move the certified organization to historical market data/replay while preserving the same agents, contracts, queues, and evaluation architecture.

**Guiding rule:** Alpha proves that the organization can live and work together. Alpha Plus proves that it can serve a client. Beta begins proving that what it learned survives contact with real historical markets.
