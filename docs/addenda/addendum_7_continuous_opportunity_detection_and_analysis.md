## Explorer + Speculator discovery, deterministic anomaly detection, report queue, deep Analysis, and client-facing ideas

### 1. Scope

This continuous loop discovers, interprets, analyzes, reports, grades, and moves on. It does not execute trades in the initial system.

### 2. Explorer Role

- Construct and inspect option universes and implied-volatility surfaces for assigned securities.
- Run deterministic statistical detectors continuously.
- Perform individual analysis: compare a security with its own local surface and expected behavior.
- Perform peer analysis: compare the anomaly with a defined peer group.
- Use lightweight LLM judgment only after a deterministic detector has produced a candidate and superficial interpretation is needed before filing a report.
- Do not perform the final deep investment thesis.

### 3. Speculator Role and Social Data

- Search external chatter for what is moving, spiking, discussed, rumored, or attracting unusual attention.
- Start with Reddit through a provider interface. Do not hard-code one community into agent logic.
- Use a shared server-side source list that agents may expand under controlled policy.
- Normalize observations into structured evidence with provenance, timestamp, source, security/topic linkage, and confidence.
- Treat social chatter as evidence, not truth; rumor must not be promoted to fact without corroboration.

### 4. Initial Volatility Anomaly

- Mental model: a mountain rising from a surrounding plain.
- The local plateau around the candidate is the baseline; the candidate region is the peak.
- Initial strong trigger: Peak IV / Local Baseline IV >= 2.0.
- A 1.5X region may be notable but does not satisfy the initial strongest trigger unless policy changes.
- The 2.0 threshold is configurable.
- The local baseline must come from an appropriate neighborhood on the volatility surface, not an arbitrary global average.
- A trigger means candidate dislocation, not guaranteed opportunity.

### 5. Individual vs Peer Analysis

- Individual analysis asks whether the security is abnormal relative to itself.
- Peer analysis asks whether the same shape or spike is occurring across comparable securities.
- If many peers move together, classify the event as potentially market/sector/common-factor driven.
- If the anomaly is isolated while peers remain normal, classify it as idiosyncratic and investigate security-specific causes.
- Peer groups must be explicit and versioned so tests are reproducible.

### 6. Handoff to Deep Analysis

1. Explorer and/or Speculator detect meaningful evidence.
2. Lightweight interpretation checks whether the candidate is coherent enough to justify expensive analysis.
3. A structured report is filed into the report queue.
4. Analysis takes the next report.
5. Analysis performs deep reasoning using quantitative evidence, peer context, social/context evidence, and other permitted data.
6. Analysis produces a client-facing opportunity report with thesis, evidence, uncertainty, confidence, and reasons the idea could be wrong.
7. The result is logged and displayed. No automatic trade is executed.
8. Analysis proceeds to the next queued report.

### 7. Economic Hypothesis

One target pattern is an option whose implied volatility is unusually elevated relative to nearby or comparable parts of the surface, creating a candidate volatility-selling idea if deeper analysis supports the expectation that the dislocation may normalize. Detection finds the dislocation; Analysis decides whether the context makes it worth presenting.

### 8. Grading Feedback

- Analysis grades each Explorer/Speculator report for relevance, novelty, evidence quality, and whether deep analysis was worth the compute.
- Low-value reports create negative feedback so upstream agents learn what not to surface.
- High-value reports create positive feedback and become accomplishments when later validated.
- Later market outcomes grade Analysis recommendations and confidence calibration.
- This loop exists partly to reduce wasted AI power on reports that do not amount to anything.

### 9. Output Boundary

- Output is an informational trading opportunity for client consideration.
- Trade execution and order management are outside this specification.
- After reporting, the loop returns immediately to the next opportunity.
