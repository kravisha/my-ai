## Server/Coordinator/COO scaffolding + one Explorer + one Speculator + Analysis + training/validation foundations

### 1. Goal

Replace the stale pre-spec implementation plan with a fresh first slice that proves the control plane, discovery pipeline, grading loop, and testability before purchasing or depending on production-grade historical options data.

### 2. Build Order

1. Create the server process and internal coordinator with process registry, spawn/retire/restart commands, queues, health telemetry, and server dashboard endpoints.
2. Create the separately spawned privileged COO client with its own continuous loop, baseline population policy, health checks, scaling hooks, and decision log.
3. Define common message schemas: task, detector event, evidence item, discovery report, analysis result, grade, outcome, health metric, scaling decision, and agent record.
4. Implement one Explorer process with a pluggable market-data provider interface and deterministic volatility-surface detector.
5. Implement one Speculator process with a pluggable social-source provider; start with Reddit-compatible source abstractions and a shared server-side source list.
6. Implement the report queue and one Analysis process with deeper LLM reasoning and explicit grading of upstream reports.
7. Implement persistent organizational memory for reports, grades, confidence, outcomes, source-list changes, agent records, and test runs.
8. Implement Explorer Trainer and Speculator Trainer plus seeded scenario generation.
9. Implement validation/regression orchestration with hidden ground truth, scoring, repeatability, and promotion gates.
10. Implement the simulated clock/replay interface so synthetic, historical, and live providers can drive the same agents.
11. Add the initial COO scaling rules and health/restart hooks.
12. Run the graduation sequence: one security, repeat two or three times, then ten securities with peer analysis.

### 3. Phase A - Contracts Before Intelligence

- Define interfaces before provider-specific code: MarketDataProvider, SocialDataProvider, Clock, AgentProcess, Queue, MemoryStore, Grader, Trainer, and HealthReporter.
- Make messages serializable and versioned.
- Every message carries IDs, timestamps, producer identity, run ID, provenance, and schema version.
- Do not let agents call each other through ad-hoc in-process references; use explicit server-mediated contracts so scaling remains possible.

### 4. Phase B - Control Plane

- Coordinator implements mechanics only: spawn, stop, restart, status, queue plumbing, and dashboard state.
- COO implements policy: desired population, health evaluation, starvation/backlog response, and restart decisions.
- Baseline one instance per role.
- Record every COO decision with reason, inputs, action, and later observed result so operational decisions can also be graded.

### 5. Phase C - Discovery Slice

- Explorer consumes generated option surfaces first through the provider interface.
- Implement the initial Peak IV / Local Baseline IV >= 2.0 detector with configurable neighborhood and threshold.
- Support individual and peer analysis.
- Speculator consumes generated social/context streams first, then a Reddit provider can be wired when credentials/mechanism are selected.
- Explorer and Speculator produce structured evidence and reports, not final trade decisions.
- Analysis performs expensive reasoning only on queued candidates.

### 6. Phase D - Training and Regression

- Explorer Trainer creates known volatility mountains, subtle anomalies, peer-wide events, isolated events, noise, missing data, and threshold-boundary cases.
- Speculator Trainer creates useful chatter, irrelevant chatter, coordinated noise, rumors, conflicting evidence, and delayed corroboration.
- Validator knows ground truth and grades every meaningful task.
- Every discovered bug becomes a permanent regression case.
- Simulation Fidelity metrics are stored from day one so generated data can later be compared with real historical data.

### 7. Phase E - Data Evolution

- Do not couple the first build to a paid vendor.
- After simulated certification, add a HistoricalOptionsProvider and acquire real intraday options data.
- Historical replay must enforce simulated time and prevent look-ahead.
- In parallel, add live ingestion/paper-research when ready.
- Real data is used both to validate the trading methodology and to improve simulation fidelity.

### 8. Phase F - Acceptance Criteria

- Server starts and reliably spawns COO first.
- COO can create the baseline team through the coordinator and observe health.
- Explorer detects injected anomalies deterministically and correctly distinguishes peer-wide from isolated cases in the graduation suite.
- Speculator produces structured, attributable reports from simulated social streams.
- Analysis consumes the queue, produces a client-facing opportunity report, assigns confidence, and grades upstream work.
- Grades and outcomes persist across process restarts.
- COO demonstrates both starvation scaling and backlog scaling in tests, then returns toward baseline.
- Regression runs are reproducible from seed/run ID.
- No test requires trade execution.
- All critical behaviors have automated tests and observable logs.

### 9. Explicitly Deferred

- Full production historical-data vendor integration and cost optimization.
- Advanced portfolio analysis.
- Automated trade execution.
- Complex financial objective optimization for COO.
- Full Chief Intelligence Officer implementation.
- Large-scale multi-host orchestration.
- Automatic production self-modification.

### 10. Developer Guiding Rule

Claude Code should treat grading as a cross-cutting requirement. When implementing any meaningful action or artifact, ask: who evaluates this, what is the score or outcome, where is it persisted, and how does the feedback return to the producer? If those answers are absent, the feature is incomplete.

### 11. Conflict Rule

- Do not silently override an existing requirement when a new statement appears to conflict with it.
- If two requirements cannot both be true, stop implementation at that decision point and request clarification.
- After clarification, update the canonical specification so the implementation has one internally consistent rule.
- Do not preserve stale alternatives merely because they appeared in an older plan.
