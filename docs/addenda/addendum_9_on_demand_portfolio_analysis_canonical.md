## Initial separate client-triggered pipeline; intentionally lean until detailed portfolio requirements are specified

### 1. Scope

Portfolio analysis is a separate pipeline from continuous market discovery. It is intentionally basic in the first implementation and will receive deeper specifications later.

### 2. Trigger and Lifecycle

1. A client explicitly requests portfolio analysis and supplies portfolio information.
2. The request reaches the backend.
3. The COO directs the coordinator to create or allocate a Portfolio Analyst process.
4. The Portfolio Analyst combines the supplied portfolio information into a unified analytical view.
5. It performs the requested analysis using relevant portfolio data and, where useful, opportunity information already available to the backend.
6. It returns a client-facing report.
7. The on-demand process may exit or return to an idle pool according to later lifecycle policy.

### 3. Initial Responsibilities

- Normalize and reconcile positions sufficiently to analyze the portfolio as a whole.
- Combine duplicate or overlapping exposures where appropriate.
- Summarize holdings, concentrations, directional exposure, issuer/sector exposure, and diversification when data permits.
- Summarize option positions and basic option exposure when available.
- Relate relevant detected opportunities to the current portfolio when useful.
- Do not automatically execute trades.

### 4. Separation from Continuous Discovery

- Continuous Explorer/Speculator discovery runs without waiting for a portfolio request.
- Portfolio analysis begins because the client asks for it.
- Opportunity reports may be inputs to portfolio analysis, but the workflows remain architecturally separate.
- Do not let portfolio-analysis requirements complicate the first continuous-discovery implementation.

### 5. Deferred Detail

- Exact account/file ingestion formats.
- Detailed merging, deduplication, and reconciliation rules.
- Greeks, scenario analysis, stress testing, correlations, factor exposures, and risk limits.
- Tax-lot and account-type treatment.
- Detailed scoring of opportunities against holdings.
- Portfolio optimization, rebalancing, and any execution functionality.

### 6. Grading

- Portfolio reports must also follow the system-wide principle that meaningful work is graded.
- Future grading should measure factual correctness, completeness, usefulness, risk identification, and downstream client value.

### 7. Conflict Rule

- Do not silently override an existing requirement when a new statement appears to conflict with it.
- If two requirements cannot both be true, stop implementation at that decision point and request clarification.
- After clarification, update the canonical specification so the implementation has one internally consistent rule.
- Do not preserve stale alternatives merely because they appeared in an older plan.
