If this specification appears to contradict an existing specification or a future requested change, stop and seek clarification before implementing the contradictory behavior.

This document specifies the continuous market-opportunity loop. Portfolio analysis is intentionally separated into its own specification.

## 2. Architectural Model

The system uses a client/server architecture. The server is the persistent backend environment in which the long-running processes and concurrent workers operate.

Server: persistent backend host for the system.

Coordinator: lives inside the server. It is an execution/factory-management component, not a decision maker.

COO / Monitoring Agent: a separately spawned privileged client process. It is the autonomous operational authority for the agent ecosystem.

Backend workers: all concurrent workers execute within backend processes.

GUI: the server has a dashboard produced by the coordinator. The COO/monitor also has an interface for observing its operational state and decisions.

## 3. Authority and Control

The coordinator does not decide what agents should exist, how many should run, or what scaling policy should be used. It executes directions from the COO.

The server starts first.

The server/coordinator spawns the COO as the first privileged client process.

The COO decides which other agents must be created and instructs the coordinator to create or retire them.

The COO is the operational boss of the autonomous agent organization.

For the initial implementation, the default population is one agent/process of each required type.

## 4. COO / Monitoring Agent Responsibilities

Continuously monitor physical system health: processes, resource availability, failures, bottlenecks, and resource crunches.

Continuously monitor ecosystem health: whether defined objectives are being met or showing expected progress.

Monitor agent utilization, queue depth, throughput, and idle time.

Autonomously adjust worker populations through the coordinator.

Raise alarms when system resources or processes are unhealthy.

Operate continuously in the backend and never depend on a human keeping a window open.

Future objectives may include workload targets, capacity optimization, and maximizing the financial returns produced by the overall system.

The COO must not demand more work than the physical system can safely handle. As the design matures it should estimate maximum sustainable load and operate within that capacity.

## 5. Initial Conservative Scaling Policy

The first version intentionally stays simple. One instance of each agent type is the normal baseline.

If a downstream analysis agent remains idle for an extended period, initially approximately one hour and configurable, the COO investigates whether the upstream Explorer/Speculator pipeline is simply not producing enough candidate reports.

If upstream agents are healthy and actively searching but have produced no work, the COO may temporarily increase the number of upstream search/detection workers to search faster.

Example initial response: add two additional upstream workers, observe whether useful work begins to arrive, and withdraw the temporary workers after the need disappears.

If the analysis/report queue grows faster than the Analysis Agent can consume it, the COO increases analysis capacity.

Scaling is therefore demand-driven: scale producers when consumers are starved; scale consumers when queues are backing up; return toward the one-per-type baseline when the temporary need ends.

## 6. Deterministic Detection Principle

Market detection must be deterministic. LLMs are not used as the primary detector.

Statistical detectors execute known algorithms and thresholds.

Examples include percentile tests, surface comparisons, local-outlier tests, and other deterministic quantitative rules.

The detector produces structured data/events, not narrative conclusions.

Only when deterministic output becomes sufficiently interesting or meaningful is an LLM invoked for interpretation and deeper analysis.

This separation is a core architectural rule: deterministic code detects; LLMs analyze.

## 7. Startup and Continuous Opportunity Cycle

Start the server.

Start the coordinator within the server.

The coordinator spawns the COO privileged client process.

The COO initializes the operating cycle and instructs the coordinator to spawn one instance of each required agent/process.

The COO supplies initial work, including a starting securities/watch list.

The Explorer begins constructing the option universe and option-volatility surfaces for the supplied universe.

In parallel, the Speculator searches external market context such as message boards, market chatter, tips, unusual activity, and narratives about what is moving, spiking, or driving markets.

Explorer and Speculator remain primarily in deterministic/statistical mode while searching.

When deterministic tests identify meaningful information, the relevant process wakes the LLM analysis capability to interpret the signal.

Explorer and Speculator exchange meaningful findings when useful so quantitative surface anomalies can be compared with external context.

When the agents have enough evidence that an item is worth deeper examination, they file a structured report into the report queue.

The Analysis Agent takes the next report from the queue, performs deeper analysis, and produces a client-facing opportunity report.

The output is an informational trading opportunity: for example, "this appears to be a potentially attractive trade opportunity; consider it." The system does not execute the trade in this loop.

The completed result is logged/displayed, and the Analysis Agent takes the next item from the queue.

## 8. Initial Definition of a Meaningful Volatility Anomaly

The first detector should identify local implied-volatility dislocations on an option surface. The mental model is a mountain rising from a surrounding plain.

The surrounding/local plateau is the baseline or "base of the mountain."

The candidate point/region is the peak.

Initial meaningful threshold: Peak IV / Local Baseline IV ≥ 2.0.

Example: surrounding comparable surface points trade around X volatility while the candidate region trades around 2X. A 1.5X region may be notable, but the initial trigger for the strongest anomaly is 2X.

The 2.0 ratio is a configurable starting parameter, not a permanent universal constant.

The local baseline must be derived from an appropriate surrounding region of the volatility surface rather than from an arbitrary global average.

A trigger is a candidate dislocation, not proof of a profitable trade.

## 9. Economic Hypothesis Behind the Detector

The target use case is identifying options whose implied volatility is unusually elevated relative to nearby/comparable parts of the same surface. One contemplated strategy is selling an option when its volatility is locally extreme, based on the hypothesis that the dislocation may normalize in the near future. The system's job at this stage is to detect and analyze the anomaly, not to assume that normalization will occur.

## 10. Reports and Handoff

Explorer/Speculator reports are structured evidence packages, not final recommendations.

The report queue is the explicit handoff boundary between opportunity discovery and analysis.

The Analysis Agent converts queued evidence into a client-facing assessment.

The loop terminates for that opportunity after reporting. It then immediately proceeds to the next queued opportunity.

Trade execution is outside the scope of this specification.
