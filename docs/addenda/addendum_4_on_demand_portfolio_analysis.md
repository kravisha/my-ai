## 1. Status and Scope

This is intentionally a lean initial specification. Portfolio analysis is a separate pipeline from the continuous market-opportunity detection loop. Detailed portfolio-analysis logic will be added later.

## 2. Interpretation Rule

Do not silently override existing requirements if a contradiction is discovered.

If this document, an existing specification, or a future requested change conflicts with another requirement, seek clarification before implementation.

After clarification, maintain a single internally consistent implementation.

## 3. Trigger and Lifecycle

A client explicitly requests a portfolio analysis.

The client supplies the portfolio information required for the analysis.

The request is sent to the backend.

The COO directs the coordinator to create the Portfolio Analyst Agent/process as needed.

The Portfolio Analyst performs the requested analysis against the combined portfolio information and relevant option/opportunity information available to the system.

The Portfolio Analyst returns its analysis to the requesting client.

This is an on-demand job rather than a continuously running market-discovery loop. Its detailed lifecycle and persistence policy can be refined later.

## 4. Initial Portfolio Input Model

Accept portfolio information from the client, potentially representing multiple accounts or portfolio sources.

Combine the supplied holdings into a unified analytical view.

Normalize and reconcile positions sufficiently to analyze the portfolio as a whole.

Use relevant option and opportunity information already available to the backend when useful.

## 5. Initial Analysis Responsibilities

For the first implementation, perform standard/basic portfolio analysis rather than attempting an exhaustive institutional risk platform.

Summarize holdings and major position concentrations.

Combine duplicate or overlapping exposures where appropriate.

Review asset, sector, issuer, and directional concentration when data permits.

Summarize option positions and basic option exposure when available.

Identify obvious concentration, diversification, and portfolio-balance observations.

Relate relevant detected trading opportunities to the existing portfolio when useful, without automatically executing any trade.

Produce a clear client-facing portfolio analysis report.

## 6. Separation from Continuous Opportunity Detection

The continuous system discovers and analyzes market opportunities without waiting for a client request.

The Portfolio Analyst is invoked because the client asks for portfolio analysis and supplies portfolio data.

Portfolio analysis must not be mixed into the continuous Explorer/Speculator discovery loop.

Opportunity reports may be used as an input to portfolio analysis, but the two workflows remain architecturally separate.
